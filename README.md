# Codex Meter

只监测当前 Windows 用户的 Codex 账号额度和当前桌面对话。原生 WinForms、.NET 8、无第三方运行库、无 WebView/Electron、无遥测和更新检查。

## 使用

双击 `dist\CodexMeter.exe`。Codex 打开时显示托盘图标和跟随其窗口右下角的窄竖排悬浮窗。

- 单击系统托盘图标：在该显示器的桌面工作区右下角打开指标面板，可见边缘紧贴屏幕右侧与任务栏上缘，并补偿 Windows 的透明边框；切换大小档位时保持这个右下角锚点，标题栏和可见边框均留在屏幕内，不随 Codex 窗口移动。面板和美元详情都不在任务栏显示。面板是普通的非置顶窗口，点击别处后收起；右键菜单和已打开的美元详情不会被立即收起。关闭面板会继续后台运行。
- 面板“当前对话”一行显示对话轮次：按唯一 `turn_id` 统计已开始的执行轮次，重复日志及工具调用不增加轮次；切换对话会同步更新。大日志也会补数较早的轮次，不只统计末尾片段。
- 托盘面板采用统一文字基线排版：同一行的标签、数值、轮次、状态按各字号的字体上升部对齐。美元剩余值和总量使用固定列，不随金额位数左右漂移。
- 状态条：单击查看详情，悬停查看重置时间及 TPS 计算依据，右键打开菜单。
- 开始页、默认宽度或输入框右侧空间不足时，两根额度条按剩余量从底部向上填充，左右分别为 5 小时与周额度，文字保持正向。拉宽窗口、右侧摘要区留出足够空白后，恢复完整的 5 小时、周额度、上下文、缓存、输入、输出和 TPS。完整模式约 **188×206 DIP**，其中横向额度条贯穿内容区并与左右文字边缘对齐；两种模式的逻辑尺寸固定，仅跟随系统 DPI，不因可用空间不足而缩小。
- 右键“托盘面板大小”可切换 67% / 85% / 100%，**只调整详情面板**。
- 面板采用 360×484、332×374、300×316 DIP 三档内容排版。100% 不再直接展开为大面板：可用高度或宽度不足时，自动切换更紧凑的档位，并把标题栏、边框一起算入空间限制；总高度控制在可用窗口高度的约72%内。85%和67%分别指定更紧凑的上限。正文保持正常字号，极窄空间才进一步适配；省略的信息在悬停提示和美元详情中可查，操作仍可通过右键菜单使用。
- 悬浮窗固定白色，输入数值使用绿色 `#10B981`，输出数值使用紫色 `#8B5CF6`；缓存使用常规字重，上下文使用浅灰色。百分比、输入输出及 TPS 数值均按固定列对齐。
- TPS 悬浮显示只保留数字和固定右对齐的 `t/s` 单位，数字在单位左侧变化。“短／旧”样本信息显示于悬停提示和详情面板，不占悬浮栏位置。
- 右键“主题”可切换白色、黑色、Miku 青绿，**只改变托盘面板和美元详情**。额度充足时悬浮栏进度条为 Miku 青绿，剩余低于 40% 后逐渐转红。
- 使用 DWM 可见窗口边界，右侧预留 **28 DIP**，包含系统滚动条、边缘拖动区域和额外点击间距；通过 Windows 辅助功能接口只读查找发送/停止按钮及输入框容器边界，与聊天输入框底部对齐。纯移动时平移已确认的锚点，窗口调整尺寸时等待边界稳定后重新测量；测量期间检查宿主位置是否变化，避免过期结果导致跳动。不读取或修改输入框文字。
- 状态条随 Codex 窗口移动、缩放、最小化、恢复；切到其他应用时隐藏，不全局置顶。不会修改或注入 Codex 安装文件，也不是真正修改 Electron 的 DOM。
- 拖动时由当前宿主窗口的位置事件唤醒跟随，并按所在显示器的实际刷新率用高精度时钟更新位置，保留59.94等小数刷新率；跨屏或显示设置改变时重新匹配。静止后时钟休眠，不忙等；普通移动复用现有画面，不重画、不重新布局，也不提高额度、日志或输入框边界的采样频率。
- 详情面板不绑定为 Codex 的所属窗口，也不在定时器中反复提高层级。仅用户点击打开时激活，离开后收起，避免挡住工作区。
- 新聊天、项目欢迎页和默认宽度的对话使用固定 **72×188 DIP** 的双竖条额度窗，使用 `5h` 和 `周` 标签并显示百分比。只有已识别当前对话、且完整指标窗能放在输入框右侧时才展开；否则使用双竖条。若正常锚点连双竖条也放不下、输入框边界未取得或尺寸变化尚未确认，则直接隐藏，不缩小、不移到输入框上方或其他位置。两种模式始终保留右侧安全间距与输入框底部锚点。
- 托盘面板的“命中量 7.04M”表示当前对话累计命中缓存约704万个 token；`M` 为百万，`k` 为千。缓存率是命中量占累计输入的比例，悬停可查看精确计数。美元总估算与左列剩余估算采用相同列内缩进。
- 面板的“美元估算…”显示自动校准详情、误差区间、样本和三模型价格，不再要求手填满额基准。
- Codex 完全关闭后，释放指标监测、文件监听、IPC、托盘和查询任务；只留无界面的启动监听，以便下次 Codex 打开时自动恢复。
- 自动启动由 Windows 任务计划独立运行，避免从 Codex 工具会话启动的进程在应用退出时被一并回收。只使用当前登录用户的交互令牌和最低权限，不需要密码，不修改 Codex 的启动命令。程序以低于正常的优先级运行；主窗口出现约2秒后才初始化监测，Codex关闭时每秒检查一次窗口是否重新出现。
- 托盘菜单“完全退出”：同时退出启动监听；“登录后自动跟随 Codex”可开关当前用户的登录启动。
- `scripts\Enable-AutoFollow.ps1` 注册并立即启动独立的登录跟随任务；`Disable-AutoFollow.ps1` 删除该任务和旧的登录启动项。不自动打开 Codex，不创建服务、不修改 Codex 配置。异常退出由 Windows 最多重试3次、间隔1分钟；从托盘正常退出不重试。

需要 Windows x64 和 **.NET 8 Desktop Runtime**。小体积版本不捆绑运行时；实际大小以文件为准。

**首次启动报 `0x80070002`：** 请使用 0.5.6 或更新版本。0.5.5 在未创建自动跟随计划任务的新电脑上，可能把“任务不存在”当作未处理异常；这与程序文件丢失无关。修复原因、本机处理及重新发布步骤见 [排错说明](TROUBLESHOOTING.md)。

发布压缩包采用文件白名单生成，不包含开发者的登录凭据、账号绑定缓存、会话日志、未选定的诊断截图或本机设置。文档中的两张布局预览使用合成数字，不代表实际账号额度。首次运行时读取使用者自己已登录的 Codex，偏好和本机校准数据只在本机生成。

## 指标与边界

| 指标 | 数据来源与定义 |
| --- | --- |
| 5 小时、周剩余 | `codex app-server` 的只读 `account/rateLimits/read`；`100 - usedPercent`。按窗口分钟数 300/10080 匹配，不将其他窗口冒充为 5 小时或周额度。 |
| 重置时间 | 服务端 Unix 时间戳，转换为 Windows 本地时区，同时显示剩余时间。到期后显示“待刷新”，不自行假定已经恢复 100%。 |
| 上下文占用 | 当前对话最新模型调用的 `last_token_usage.total_tokens / model_context_window`，不是把所有轮次输入相加；不额外扣除猜测的系统提示长度。 |
| 输入、输出 | 当前对话的累计官方 token 计数；输出含推理 token。 |
| 缓存命中 | 累计 `cached_input_tokens` 及其占累计输入的百分比；缓存是输入的子集，不重复加到总输入。 |
| TPS | 最近一个完整的 `final_answer` 正文响应：`usage.output_tokens - usage.reasoning_output_tokens` 除以该响应 `AgentMessage` 时间区间并集。只有最终回答且无工具调用的响应才采样；排除推理、工具参数、工具执行、用户等待和中途说明，按 response ID 去重。 |
| 美元估算 | **总量 ≈ API 等价成本增量 / 额度百分比增量 × 100；剩余 ≈ 总量 × 剩余比例**。分别估算 5 小时和周额度，不把两档相加。需要至少 3 个百分点的同重置窗口变化，否则显示采样中。 |

TPS 是**上一次最终回答正文的日志估算**，不是实时流量计或精确的模型解码速度。它随完整日志更新；接受至少 250 毫秒、8 个正文 token 的样本。小于3秒或128 token时显示“短”，短样本可能受缓冲交付影响而显著偏快；超过2分钟显示“旧”，保留上次值。悬停可看准确采样时间、token数、计时区间。只有缺少有效样本时才显示 `—`；完整回答与工具调用混合、中断消息、中途说明、零耗时样本均不计入。不把结果人为限制在某个速度范围。输入/输出和上下文以最新已落盘记录为准。

额度启动时查询，之后每 5 分钟查询一次，也可手动刷新；查询时短暂启动 Codex 自带的 app-server，完成或 20 秒超时后结束该子进程，不常驻另一套服务器，不发起模型对话。接口失败时保留最近额度并标明状态，使用本地日志作为补充。额度面板显示来源和采样时间。若账号没有某一档窗口则显示 `—`。

美元校准只定价 GPT-6 Astra、GPT-6.1 Sol、GPT-6.1 Terra。每百万 token 标准 API 输入/缓存读/30分钟缓存写/输出价分别为 10/1/12.5/50、2/0.1/2.5/10、1/0.05/1.25/5 美元，2026-10-30 核对[官方价格表](https://developers.openai.com/api/docs/pricing?latest-pricing-expanded=true)。普通输入扣除缓存读写，推理 token 已包含在输出内；输入超过272k时按官方长上下文输入/缓存2倍、输出1.5倍计算，不额外推测加速模式溢价。

校准首次读取本机最近8天的会话与归档数字记录，按账号隔离、按 response ID 去重，之后每30秒增量更新。总量和剩余量都是动态估计；模型混合、缓存比例、长上下文和取整都会使总量估计变化。当前账号优先取自额度接口；确认换号时立即隐藏旧账号估值，即使继续使用旧账号创建的对话，后续消耗也归到新账号。已观察到的归属时间线以 SHA-256 账号键写入 `%LOCALAPPDATA%\CodexMeter\account-bindings.json`，重启后继续使用；不保存原始账号ID。换号确认随额度接口刷新（每5分钟或手动刷新），未曾观察到的历史换号无法精确追溯。

重置和百分比回退会断开样本；包含未知模型成本的区间不参与拟合。显示的区间反映百分比取整误差，不包含全部统计误差；其他设备/云端消耗、缺失日志和不同模型的套餐计量方式都会影响估算。这是当前使用模式下的 API 等价美元，不是官方余额。不保存聊天正文，不发起额外模型调用。

当前对话优先只读获取所附着 Codex 窗口的网页文档标题，与本机 `session_index.jsonl` 中的唯一对话 ID 匹配，包括空闲对话。IPC 的消息流跟随事件可能仍指向旧页面或后台对话，因此只在页面信息不可用时作为回退；IPC 也不可用时才使用最近活跃的桌面对话，并在100%面板标明来源。已识别页面但没有唯一匹配（包括重名或尚无本机索引）时不猜测其他对话。页面识别不读取聊天正文或输入框文字，不发送 UI 输入。远程会话没有本机日志时不显示其他对话的数据。

## 数据、体积与范围

- 只保留额度数字、模型名、对话 ID、token 计数和输出时间区间；不保存聊天正文。
- 会话根目录为 `$CODEX_HOME/sessions`，未设置时为 `~/.codex/sessions`。只识别首行 `originator=Codex Desktop` 且 `source=vscode` 的根会话，排除子代理重放。
- 首次建立文件名索引；文件系统事件驱动后续索引更新，每 5 分钟补扫一次。活动日志每秒检查并增量读取；首次最多读末尾 16 MiB，保留未写完行，单行上限 2 MiB。
- 偏好保存到 `%LOCALAPPDATA%\CodexMeter\settings.json`（面板缩放、主题、可见性、美元基准）；自动跟随使用任务计划 `CodexMeter.AutoFollow-<当前用户SID>`。启用成功后移除旧的 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run\CodexMeter`，避免重复启动。注册失败的诊断写入设置目录的 `startup-error.txt`。
- 程序不直接访问登录凭据文件或浏览器 cookie；额度由 Codex 自带客户端处理。除 Codex 自带额度查询外没有网络请求。
- 不采集 CPU、内存、网络流量、其他 AI 服务或账户数据，不上传会话数据；窗口跟随仅检查 Codex 主窗口的存在、位置和可见状态。
- 卸载：先取消自动跟随或运行 `Disable-AutoFollow.ps1`，再从托盘完全退出并删除解压目录；如需清除偏好，再删除上述 CodexMeter 设置目录。

本地 JSONL 和 Desktop IPC 属于内部格式，Codex 升级后可能需要适配。可执行文件没有代码签名。

## 构建与验证

需要 .NET 8 SDK。`scripts\Build.ps1 -DotnetPath <dotnet.exe路径>` 先运行合成数据检查，再生成共享运行时的单文件 exe。

`scripts\Package.ps1 -DotnetPath <dotnet.exe路径>` 在独立目录重新构建并检查发布内容，生成 `artifacts\CodexMeter-v<版本>-win-x64.zip`、源码压缩包及 `SHA256SUMS.txt`，不会打包现有 `dist` 中的诊断数据，也不会替换运行中的程序。

开发诊断参数：

```powershell
.\dist\CodexMeter.exe --show
.\dist\CodexMeter.exe --probe --online
.\dist\CodexMeter.exe --preview
.\dist\CodexMeter.exe --follow-benchmark
```

`--probe` 向 exe 目录写入 `probe.json`（对话 ID、数字指标和进程私有内存，不含正文或凭据）；`--online` 加一次真实只读额度查询。`--preview` 使用合成数字渲染界面 PNG，并输出不同 DPI 和窗口大小下的布局报告。`--attachment-check` 检查原生窗口锚点、非置顶状态及面板失焦收起，仅操控测试窗口。诊断文件不打包到便携压缩包。

`--follow-benchmark` 用独立测试窗口对比旧版150毫秒轮询和显示器节奏跟随，记录更新次数、CPU、内存与重绘次数，并测试高刷新率时钟；不移动使用者的Codex窗口。CPU按全部逻辑处理器归一化，结果受当时系统负载影响。`--trace-attachment` 报告当前显示器Hz、原生事件跟随和高精度时钟是否启用，方便本机排查。
